# 开发工作文档

`docs/dev/` 保存需要开发者审阅的产品设计、重要决策和执行记录。开发者同时承担产品经理角色，因此文档首先服务于快速理解和决策，其次才是 Agent 的执行依据。

## 核心目的

每份文档只需回答四个问题：

1. 是否准确理解并完善了开发者的初步意图？
2. 推荐设计是什么，关键取舍和边界是什么？
3. 如何以可观察、可重复的方式验收？
4. 获得执行授权后，目前做到哪里、下一步是什么？

文档不是冻结的完整规格，也不能代替执行时对当前代码、依赖文档和最佳实践的核查。

## 写作原则

- **结论优先**：先给推荐方案和用户可感知行为，再补充必要理由。
- **产品视角优先**：先说明用户体验、状态、规则、边界和取舍；代码结构只在影响决策或验收时说明。
- **最小充分**：只保留审阅、执行和验收所必需的信息，不预写完整实现。
- **区分确定性**：明确标出已决定、待确认、技术假设和非目标，不把 Agent 推测写成既定要求。
- **验收具体**：使用可观察行为、自动测试和必要的人工步骤，避免不可判定表述。
- **开发者操作可执行**：需要开发者操作外部网站、桌面界面或账号时，单列准确入口、字段、预期结果、需反馈信息和安全边界。
- **进度可见**：长任务维护简短清单、当前步骤、验证结果和阻塞项，不记录逐命令流水账。
- **保持开放**：约束目标、外部行为和验收标准，不锁死内部实现。
- **重大变化回审**：新证据改变产品行为、范围、外部契约或验收标准时，先更新文档并交由开发者审阅。
- **一个权威版本**：同一决策优先更新现有文档；推翻核心方案时新建下一编号文档并链接旧文档。

一般正文建议控制在 50–120 行，复杂任务尽量不超过 150 行。超过时优先删除重复背景、推测性设计和低层实现细节。

## 状态与授权

文档状态和执行授权必须分开：

| 状态 | 含义 |
| --- | --- |
| `Draft` | 等待开发者审阅，设计仍可调整 |
| `Approved` | 设计方向已确认，但仍以“执行授权”字段为准 |
| `In Progress` | 已获授权并正在实施 |
| `Pending Validation` | Agent 已完成实现和自身验证，等待开发者验收 |
| `Completed` | 验收通过，无待办项；等待下一次发布前清理 |
| `Superseded` | 已被另一份明确链接的文档取代；等待下一次发布前清理 |

依赖变更、安装全局软件、破坏性操作、提交、推送和发布仍遵循根目录 `AGENTS.md`，不能由工作文档自行扩大授权。

## 最小结构

```markdown
# 标题

| 字段 | 内容 |
| --- | --- |
| 状态 | Draft |
| 更新 | YYYY-MM-DD |
| 目标 | 一句话说明要解决的问题 |
| 执行授权 | 未授权 / 已授权（日期和范围） |

## 1. 结论与设计

- 推荐方案、用户行为、关键边界和非目标

## 2. 待确认

- 只列会改变结果、需要开发者决定的问题；没有则写“无”

## 3. 开发者操作（如需）

- 仅保留开发者必须亲自完成的外部或交互式步骤

## 4. 验收

- [ ] 核心行为、边界、自动验证和必要人工步骤

## 5. 执行进度

当前：未开始
下一步：等待执行授权
验证：未开始
阻塞：无
```

章节可按任务缩减，不要求机械套用。

## 执行规则

1. Agent 先核查相关行为、当前仓库和权威资料，再完善开发者的初步意图。
2. `Draft` 阶段只讨论和更新文档，不自动实施其中方案。
3. 获得执行授权后，动手前重新核对当前代码与依赖能力。
4. 执行中维护简短进度；重大设计变化暂停对应实现并回审。
5. Agent 完成实现和自身验证后标记 `Pending Validation`；开发者验收通过后再标记 `Completed`。
6. 被替代文档标记 `Superseded` 并链接新的权威文档。

## 生命周期与 Git 留档

`docs/dev/` 是当前开发工作的工作区，不是永久档案：

1. 工作文档在设计、实现和验收期间保留，并随功能提交进入 Git 历史。
2. 文档完成或被取代后，先确保最终内容已经提交并可通过 Git 追溯。
3. 新版本发布前审查 `docs/dev/`，仅保留仍在进行、待验收或下一版本继续使用的文档。
4. 删除工作文档需列入发布准备并获得明确授权；`docs/dev/README.md` 永久保留。

## 命名与语言

- 文件命名为 `<major>.<minor>-<sequence>-<topic>.<ext>`。
- `<major>.<minor>` 表示产品版本线；`<sequence>` 使用两位编号并从 `01` 起递增。
- `topic` 使用简短英文 kebab-case。
- 本 `README.md` 不参与编号。
- 正文默认使用中文；代码、命令、文件名和专有名词保留英文。
